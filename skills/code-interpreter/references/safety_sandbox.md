# Code Interpreter Safety & Sandboxing Policies

This document outlines execution boundaries, safety envelopes, and resource guards for executing untrusted scripts locally.

---

## 1. Execution Timeout Envelopes

* **Default Timeout:** 10,000 ms (10 seconds).
* **Maximum Allowed Timeout:** 30,000 ms (30 seconds) for heavy computations.
* **Timeout Behavior:**
  - If a script exceeds the designated threshold, the subprocess must be terminated immediately.
  - Return a structured timeout report (`EXECUTION_TIMED_OUT`) explaining that execution exceeded the safety limit.

---

## 2. Resource Exhaustion & Infinite Loop Guards

* **Loop Protection:**
  - Avoid unbounded loops (`while True:` without a deterministic exit condition).
  - Use bounded iterations:
    ```python
    for _ in range(10000):
        # bounded work
    ```
* **Memory Constraints:**
  - Disallow generating multi-gigabyte in-memory arrays or reading massive binary dumps in memory.
  - Keep scratchpad memory footprint under 256MB.

---

## 3. Destructive Command Prevention

* **Strict Ban on Destructive Shell Invocations:**
  - Scripts generated by the Code Interpreter must NEVER invoke destructive filesystem operations (`os.remove('/')`, `shutil.rmtree('..')`, `rm -rf`, or formatting disk volumes).
  - Scripts must confine file writes to the designated `scratch/` workspace directory.

---

## 4. Scratchpad File Hygiene

* **File Location:** Always write temporary scripts inside the workspace `scratch/` folder:
  - `scratch/eval_run.py`
  - `scratch/eval_run.js`
* **Post-Execution Cleanup:** Upon capturing stdout/stderr, remove the temporary scratch file unless the user explicitly asks to preserve the generated script.
